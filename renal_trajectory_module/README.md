# Renal Trajectory Simulation Module

This module provides a hypothetical longitudinal renal-function simulation for research use. It wraps an existing mechanistic implementation; the equations and implementation were not independently developed or changed here.

## Install and run

Run these commands from the repository root:

```bash
python -m pip install -r renal_trajectory_module/requirements.txt
python renal_trajectory_module/examples/example_simulation.py
python -m pytest renal_trajectory_module/tests
```

The package can be imported when the repository root is on `PYTHONPATH` or is the current working directory.

## Inputs and outputs

The simulator accepts four baseline measurements:

- `egfr0`: eGFR in mL/min/1.73m².
- `a1c`: HbA1c in percent.
- `uacr0`: urine albumin-to-creatinine ratio in mg/g.
- `sbp`: systolic blood pressure in mmHg.

It also accepts `years` for the simulation horizon (default 15 years), `n` for the number of evenly spaced output points (default 400), `u` for the model's treatment-effect scalar (default 0), and optional parameter mapping `p` (default: bundled `TRIAL_CALIBRATION_V2`). The application adapter currently uses `u=0`, `p=None`, and limits the requested horizon to greater than 0 and at most 15 years.

Example call using illustrative values:

```python
from renal_trajectory_module import simulate_trajectory_v2

time_years, simulated_egfr, simulated_uacr, time_below_15 = simulate_trajectory_v2(
    egfr0=47.7,
    a1c=8.1,
    uacr0=145.0,
    sbp=142.0,
    u=0.0,
    p=None,
    years=5,
    n=400,
)
```

The function returns time points, hypothetical eGFR and UACR values, and the interpolated time when eGFR first falls below 15. If that threshold is not crossed during the simulated horizon, the threshold time is positive infinity. UACR is generated by the model as an output; it is not held constant as an input.

## Model behavior and limitations

The implementation initializes its state from `egfr0`, integrates it with SciPy `solve_ivp` (LSODA), maps the state to eGFR, and derives UACR. Model constants and defaults are defined in `model_core.py`. These equations and their output semantics are inherited from the attributed upstream implementation.

This deterministic output is a hypothetical research simulation, not a validated patient-specific forecast, diagnosis, or treatment recommendation. It does not represent continuous monitoring or establish that any intervention causes a change in outcome. The original function does not provide comprehensive input validation; malformed inputs may raise native NumPy/SciPy errors or produce non-finite values. Callers should provide finite numeric measurements, a nonnegative horizon, a positive integer `n`, and a compatible parameter mapping when overriding defaults.

Bundled parameters are trial-anchored defaults; the module does not train or fit parameters and does not require calibration files or clinical datasets. Example values are illustrative and are not patient data. Runtime numerical dependencies are NumPy and SciPy.
